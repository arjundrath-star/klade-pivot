- Gate: `src/proxy.ts` (Next 16's middleware) matches `/admin`, `/admin/:path*`, `/parent`, `/parent/:path*` and sends a browser without a valid `klade_gate` cookie to `/gate?next=…`. The cookie is `expiry.HMAC-SHA256(password, "klade-gate-v1:expiry")` (`src/gate/token.ts`, `node:crypto`, compared with `timingSafeEqual`; the proxy runs on the Node runtime), good for 24 h, httpOnly, never the password. `/gate` is a plain form posting to `POST /gate/enter` (zod, `timingSafeEqual` on digests, `next` must be a gated path on this site), with an in-memory limiter of 5 wrong tries per address per 15 minutes (`cf-connecting-ip`, then `x-forwarded-for`). The proxy only keeps browsers off the pages: every parent and admin page, action and route gets its ids from `gatedFamily(next)` in `src/gate/server.ts`, which checks the cookie again and returns the demo family (sign-in is not built, so a signed-in browser is the demo parent) or redirects to the gate; `GET /api/lock-state?view=parent` uses the non-redirecting `signedInFamily` and returns 401. Real sign-in replaces that one function body. The gate and the student cookie share `httpOnlyCookie` in `src/session/cookies.ts`. With `ADMIN_PASSWORD` unset the gate stays closed and says so. Unit tests sign in through the cookie jar in `tests/setup.ts`; the smoke server runs with `smoke-gate` (`tests/smoke/password.ts`).
