# Milestone 18: Demo mode and session ergonomics

## Goal

The three-minute recording can be made without fighting the product: the chapter's read gate asks only for the confirmation, a signed-in demo driver can skip practice problems without faking results, the admin ribbon can be hidden while staying signed in, the stylus pad draws legibly with a mouse, and the demo student's session shows the same problems every time so the narration can name them.

## Scope

In:

- Read gate: "I've read this" alone completes the Learn block; stepping through the worked examples is optional and the reveal stays as a reading aid.
- Demo skip: `attempts.skipped` (migration, boolean, default false). When the request carries a valid gate cookie (the same check the ribbon uses), warm-up and guided problem cards show a small "Skip (demo)" button; the server action records an attempt with `skipped = true`, `correct = false`, no XP, and the block gate treats a skipped problem as answered. No skip exists on the exit check, the explain-back or anywhere without the cookie; a request to skip without the cookie is refused server-side. Skipped attempts show as "skipped" in the parent history and never count toward mastery, streaks, rewards or badges.
- Ribbon: a "Hide" control collapses the admin ribbon to a small pill (one client component, on demand); the choice is remembered in a cookie for that browser; the pill restores it.
- Stylus pad: strokes smoothed between pointer samples, 3 px wide, a Clear button, the pad at least 320 px tall when its tab is active; still nothing persisted; still labeled as the tablet prototype.
- Fixed demo problems: sessions opened for the demo student (Start on `/student` after Reset demo, and the seed's `--open-session`) draw their per-problem seeds from a constant `DEMO_SESSION_SEED` instead of a random one, so warm-up, guided and exit problems are identical on every run. Append to `docs/demo-runbook.md` a "Demo problems" table listing every problem of the demo session in order (block, index, the rendered text for Maya's interests, the equation, the answer) generated by the same code path, and keep it current by a unit test that renders them from the constant.
- Tests: skip refused without the cookie, skip recorded with it and excluded from XP and mastery, read gate completes on confirmation alone, fixed-seed determinism, ribbon hide cookie.

Out (do not build, even if tempting):

- Removing or reordering any problem; any change to the exit rule, the coach, the grader, the chapter content or the course data.

## Acceptance criteria

1. Signed in at the gate, a guided problem can be skipped and the block completes; signed out, no skip button renders and the action is refused.
2. After Reset demo, Start opens a session whose problems match the runbook's "Demo problems" table.
3. The Learn block completes on "I've read this" without revealing any example step.
4. Every existing smoke path passes; every route scores 90 or better; the session route stays within its 175 KB budget.
5. `scripts/gate.sh` exits 0.

## Smoke path

Sign in at the gate → Reset demo → Start → warm-up problem text matches the table → Skip (demo) twice, answer the third → Learn: confirm without revealing → guided: skip to the word problem, answer wrong, "I'm stuck" → continue as the runbook says.
